# 보일러플레이트를 내 프로젝트로 바꾸기

이 문서는 복사하거나 GitHub에서 가져온 보일러플레이트를 내 서비스에 맞게 바꾸는 확인표입니다. 프로젝트 이름·화면·제작자 정보·DB·문서·배포 설정에서 변경할 항목과 유지할 항목을 선택합니다.

먼저 [설치와 실행](SETUP.md)을 따라 기본 화면을 확인하세요. 모든 항목을 반드시 변경할 필요는 없으며, DB나 배포가 필요하지 않다면 해당 단계는 생략할 수 있습니다. 이 문서를 읽거나 확인표에 표시하는 것만으로 파일 수정·DB 생성·배포가 실행되지는 않습니다.

이 확인표는 기능 개발 계획서가 아닙니다. 새 기능은 요구사항과 현재 코드를 분석하고 관련 작업 지침을 적용해 계획합니다. 계획 파일이 필요하면 [계획 작성 안내](../plans/README.md)의 양식에 따라 초안을 확인하고 승인한 뒤 생성합니다.

## 1. 설치와 기본 화면

- [ ] 내 프로젝트 저장소를 만들고 package.json이 있는 폴더를 편집기에서 열었습니다.
- [ ] Node.js 24를 준비하고 npm ci를 실행했습니다.
- [ ] npm run dev로 기본 화면을 확인했습니다. 첫 화면에는 DB 설정이 필요하지 않습니다.
- [ ] 원 제작자의 실제 .env를 복사하지 않았습니다. DB가 필요할 때 내 .env를 만듭니다.

## 2. 이름과 기본 화면 변경

| 바꿀 항목          | 파일·위치                      | 확인할 내용                                                                                                    |
| ------------------ | ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 저장소 이름        | GitHub 저장소 설정             | 내 프로젝트를 구분할 이름을 정합니다.                                                                          |
| 패키지 이름        | package.json의 name            | 소문자 영문·숫자·하이픈을 사용하는 이름을 정합니다. 변경 시 package-lock.json의 루트 이름도 일치시켜야 합니다. |
| 브라우저 제목·설명 | src/app/layout.tsx의 metadata  | 바이브 코딩 시작 안내의 제목과 설명을 실제 서비스 내용으로 바꿉니다.                                           |
| 화면 언어          | src/app/layout.tsx의 html lang | 기본값은 ko입니다. 영어 서비스는 en처럼 실제 언어에 맞춥니다.                                                  |
| 첫 화면            | src/app/page.tsx               | 단계별 개발 안내를 참고하고, 실제 서비스의 첫 화면으로 교체합니다.                                             |
| 브라우저 아이콘    | src/app/favicon.ico            | 내 서비스의 아이콘으로 교체합니다.                                                                             |
| 공통 디자인        | src/app/globals.css            | 필요한 색상·폰트·다크 모드를 조정합니다. 기본 폰트 사용 시 빌드에서 다운로드가 필요합니다.                     |
| 정적 이미지        | public/                        | 실제 사용하는 이미지로 교체하고 화면의 참조를 확인합니다.                                                      |

- [ ] 프로젝트 이름과 화면 제목이 내 서비스와 일치합니다.
- [ ] 언어·설명·아이콘을 확인했습니다.
- [ ] 필요 없는 기본 로고·외부 링크는 사용 범위를 확인한 뒤 정리했습니다.

package.json의 이름을 바꿀 때는 관련 lock 파일도 함께 갱신해야 합니다. 패키지·lock 변경이 포함되므로 Codex에 맡길 때 변경 범위를 먼저 확인하고 승인하세요.

## 3. 제작자 정보와 라이선스

현재 package.json의 author는 보일러플레이트 원 제작자 progdper입니다. 새 프로젝트에서는 현재 프로젝트의 작성자 정보로 바꿀 수 있으며, 필요하면 contributors에 기여자를 구분해 기록할 수 있습니다. 이메일·홈페이지 등 공개할 정보만 넣으세요.

이 보일러플레이트의 [MIT License](../LICENSE)와 progdper 저작권 고지는 유지합니다. author를 바꾸는 것과 기존 라이선스·저작권 고지를 삭제하는 것은 다릅니다. 새 프로젝트의 추가 저작권 고지가 필요하면 기존 고지를 유지한 상태에서 별도로 추가합니다. 외부 패키지·이미지·폰트는 각각의 라이선스를 확인하세요.

- [ ] package.json의 작성자 정보가 의도한 공개 정보인지 확인했습니다.
- [ ] LICENSE의 원 저작권·라이선스 고지를 유지했습니다.

## 4. DB가 필요한 프로젝트

상세 절차는 [Supabase 안내](SUPABASE_SETUP.md)를 따릅니다.

- [ ] 내 개발·테스트용 Supabase 프로젝트를 준비했습니다.
- [ ] 내 프로젝트의 공식 CA를 certs/supabase-ca.crt에 저장했습니다.
- [ ] 루트 .env에 DATABASE_URL·DIRECT_URL을 설정하고 Git에서 제외되는지 확인했습니다.
- [ ] npm run db:check로 DB 변경 없이 두 연결을 확인했습니다.
- [ ] 기본 User 모델이 필요한지 확인했습니다. 이 모델은 로그인 기능이나 Supabase Auth 연동을 제공하지 않습니다.
- [ ] 테이블이 필요하면 개발 DB 변경 범위를 확인한 후 마이그레이션을 적용했습니다.
- [ ] 기능 개발 후 실제 데이터의 읽기·쓰기와 권한을 별도로 검증했습니다.

src/generated_prisma/는 자동 생성 코드입니다. 직접 수정하지 않고 prisma/schema.prisma를 기준으로 생성합니다. 다른 프로젝트에서의 기존 연결 성공 기록만으로 내 프로젝트도 성공한다고 판단하지 마세요.

## 5. README와 로컬 검사

README의 **프로젝트 개요부터 시작하는 작성 양식**은 항목 구조를 유지하고 실제 프로젝트 내용을 채웁니다. 수행하지 않은 기능·검사·배포는 완료로 표시하지 않습니다.

- [ ] 프로젝트 소개·주요 기능·실행 방법을 실제 결과에 맞게 작성했습니다.
- [ ] AGENTS.md와 .agent/의 초기 구성 설명이 현재 코드와 맞는지 확인했습니다.
- [ ] 원본 보일러플레이트의 검증 기록과 내 프로젝트의 검증 결과를 구분했습니다.
- [ ] 문서 갱신을 보류한 항목과 아직 검증하지 않은 범위를 구분했습니다.
- [ ] npm run check와 npm run build를 통과했습니다.
- [ ] GitHub에 올릴 파일에 실제 .env·node_modules·.next·생성 코드가 포함되지 않았는지 확인했습니다. 이미 추적 중인 파일은 .gitignore만으로 제외되지 않습니다.

GitHub Actions는 기본 설정에 포함하지 않습니다. 필요할 때만 [선택적 Actions 안내](GITHUB_ACTIONS.md)를 따라 도입하고, 도입한 경우에만 Windows·Linux 검사 결과를 별도로 확인하세요.

## 6. 배포가 필요할 때

- [ ] [배포 안내](VERCEL_DEPLOYMENT.md)를 확인했습니다.
- [ ] Vercel Build Command를 npm run check && npm run build로 설정했습니다.
- [ ] 로컬 .env와 별도로 Vercel 환경 변수를 설정했습니다.
- [ ] Preview와 운영 DB를 구분했습니다.
- [ ] 배포 주소에서 실제 동작과 DB 읽기·쓰기를 확인했습니다.

인터넷 공개가 필요하지 않다면 배포 단계는 생략할 수 있습니다.
