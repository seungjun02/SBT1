# 폰트 선택 안내

폰트는 기본 설정으로 시작해도 됩니다. 한글 중심 디자인, 원하는 분위기, 외부 다운로드 제한이 있을 때 선택하세요. 이 문서는 선택 안내이며 폰트 파일이나 새로운 폰트 설정을 추가하지 않습니다.

[설치 안내](SETUP.md)에서 시작하고, 화면 작업의 결정은 필요한 경우 [계획 양식](../plans/README.md)에 기록할 수 있습니다.

## 현재 구성

- `src/app/layout.tsx`는 `next/font/google`로 Geist와 Geist Mono를 불러오고 CSS 변수를 등록합니다. 설정된 subsets는 latin입니다. 이것만으로 한글 전용 글꼴이 준비되었다고 판단하지 않습니다.
- `src/app/globals.css`는 이 변수를 Tailwind의 sans·mono에 연결하지만, body의 기본 font-family는 Arial, Helvetica, sans-serif입니다. 해당 Tailwind 글꼴 클래스를 사용하는지에 따라 실제 적용이 달라지며, 한글은 사용 가능한 대체 글꼴로 표시될 수 있습니다.
- 따라서 현재 화면 전체가 Geist로 표시된다고 가정하지 않습니다. 실제 적용은 CSS와 브라우저에서 확인해야 합니다.
- 외부 폰트 import가 남아 있으면 body에서 다른 글꼴을 쓰더라도 개발·빌드 시 폰트 다운로드가 필요할 수 있습니다.

## 처음에는 무엇을 선택하나요?

| 원하는 조건                         | 검토할 선택                                               |
| ----------------------------------- | --------------------------------------------------------- |
| 우선 화면부터 실행                  | 현재 설정 유지. 기본 구성에는 외부 폰트 다운로드가 있음   |
| 한글 중심의 일관된 화면             | Pretendard·Noto Sans KR 등 한글 지원 후보 비교            |
| 빌드 시 외부 폰트 다운로드를 피함   | 허용된 폰트 파일을 프로젝트에 포함하거나 시스템 폰트 사용 |
| 추가 폰트 파일을 관리하고 싶지 않음 | 시스템 폰트. 운영체제별 표시 차이 허용 필요               |

이미 선택한 폰트가 있으면 그대로 진행합니다. DB·서버만 수정하는 작업이나 폰트와 무관한 단순 수정에는 다시 선택할 필요가 없습니다.

## 무료 폰트 후보

아래는 선택 후보이며 모두 설치할 필요가 없습니다. 실제 도입 시 선택한 배포 파일의 공식 라이선스를 다시 확인하세요.

| 후보               | 검토할 용도                            | 한글 확인                                    | 공식 출처·라이선스                                                                                                                                                    |
| ------------------ | -------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Geist / Geist Mono | 영문 UI·숫자·코드 표시, 현재 구성 유지 | 현재 latin 설정과 별도로 한글 대체 글꼴 검토 | [공식 저장소](https://github.com/vercel/geist-font), [SIL OFL 1.1](https://github.com/vercel/geist-font/blob/main/LICENSE.txt)                                        |
| Pretendard         | 한글·영문이 섞인 서비스 UI             | 한국어용 배포 파일과 필요한 굵기 확인        | [공식 저장소](https://github.com/orioncactus/pretendard), [SIL OFL 1.1](https://github.com/orioncactus/pretendard/blob/main/LICENSE)                                  |
| Noto Sans KR       | 한국어 본문·UI                         | KR용 파일·문자 범위와 용량 확인              | [Google Fonts 배포](https://fonts.google.com/noto/specimen/Noto+Sans+KR), [공식 Noto CJK Sans 라이선스](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE) |

무료 다운로드 여부와 상업적 이용·웹 임베딩·재배포 허용 여부는 구분합니다. 폰트 파일을 보일러플레이트에 포함하려면 원본 저작권·라이선스 고지를 보존하고 수정·이름 변경 등의 조건도 확인합니다. 앱의 MIT 라이선스가 외부 폰트 라이선스를 대신하지 않습니다. 라이선스를 확인할 수 없는 파일은 후보에서 제외합니다.

## 로딩 방식 비교

| 방식               | 외부 폰트를 받는 시점                                               | 장점                                         | 고려할 점                                                 |
| ------------------ | ------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------------------- |
| `next/font/google` | 개발·빌드 과정에서 필요. 배포 후에는 앱의 정적 자산으로 제공        | Next.js의 폰트 최적화 활용                   | 개발·빌드 환경에서 외부 접근이 제한되면 실패할 수 있음    |
| `next/font/local`  | 공식 파일을 처음 준비할 때 다운로드. 이후 빌드는 프로젝트 파일 사용 | 빌드 시 외부 폰트 서비스 접근을 피할 수 있음 | 파일·라이선스 포함, 용량·버전·갱신 관리 필요              |
| 시스템 폰트        | 별도 웹폰트 다운로드 없음                                           | 추가 폰트 파일 없이 시작                     | Windows·macOS·Linux·모바일에서 모양·줄바꿈이 다를 수 있음 |

`next/font/google`는 방문할 때마다 Google Fonts 서버에서 폰트를 받는 방식이 아닙니다. `next/font/local`도 방문자는 앱에서 폰트 자산을 받습니다. 로컬 파일 사용은 프로젝트 빌드의 외부 폰트 다운로드를 피한다는 의미이며 앱 전체가 오프라인이 된다는 뜻은 아닙니다. [Next.js 폰트 공식 안내](https://nextjs.org/docs/app/api-reference/components/font)

CDN 주소를 CSS에 직접 연결하는 예제는 위의 자체 제공 방식과 다릅니다. 방문자의 외부 요청과 서비스 의존성이 생길 수 있으므로 예제를 그대로 혼합하지 마세요.

## 선택 후 적용·검증

1. 현재 설정과 기존 계획의 폰트 선택을 확인합니다.
2. 후보, 한글 지원, 필요한 굵기·용량과 로딩 방식을 비교합니다.
3. 공식 출처·버전·라이선스, 추가할 파일과 수정할 CSS·레이아웃을 확인합니다. 로컬 파일 위치는 기존 구조에 맞는 최소 경로로 제안받으며 폴더를 미리 만들 필요는 없습니다.
4. 사용자 승인 후 필요한 파일과 고지를 포함하고 폰트 import·변수·실제 font-family를 연결합니다. 외부 다운로드 제거가 목적이면 불필요한 원격 import도 정리합니다.
5. 한글·영문·숫자, 필요한 굵기, 대체 글꼴, 모바일 줄바꿈·레이아웃 변화와 빌드를 확인합니다. 실제 확인 결과와 아직 확인하지 못한 환경은 구분합니다.

폰트 선택을 기록한 것과 다운로드·파일 추가·설정 변경을 승인한 것은 별개입니다. 화면에서 폰트만 바꾸기 위해 새로운 인증·DB 변경이나 라이브러리 설치가 반드시 필요한 것은 아닙니다.

```text
화면 설계를 시작하기 전에 docs/FONTS.md와 현재 폰트 설정을 확인해 주세요.
기본 설정 유지와 한글 지원 무료 폰트 후보를 비교하고,
공식 출처·라이선스·필요 굵기·용량·로딩 방식을 설명해 주세요.
이미 결정한 폰트가 있다면 유지하고, 변경이 필요한 이유가 있을 때만 제안해 주세요.
빌드 시 외부 폰트 다운로드를 피하는 선택지도 알려 주세요.
아직 파일 다운로드·추가·설정 변경은 진행하지 마세요.
```

에이전트의 구현·검증 기준은 [프론트엔드 지침](../.agent/frontend.md#화면-설계와-폰트-선택)에 있습니다.
