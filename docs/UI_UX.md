# UI/UX와 KRDS 참고 안내

UI는 버튼·입력창·메뉴 등 사용자가 접하는 화면 요소이고, UX는 목적을 달성하는 전체 사용 경험입니다. 화면을 예쁘게 만드는 것과 함께 사용자가 다음 행동을 이해하고 실수에서 회복할 수 있는지 계획하세요.

이 문서는 비개발자와 에이전트가 화면을 계획·검증할 때 쓰는 안내입니다. 문서 추가만으로 현재 화면에 KRDS 디자인이 적용되거나 접근성 검증이 완료되지는 않습니다. 기본 실행은 [설치 안내](SETUP.md)를 참고하세요.

## KRDS는 무엇인가요?

KRDS(Korea Design System)는 디지털 정부서비스의 일관된 화면과 사용 경험을 위한 원칙·스타일·컴포넌트·패턴 등을 제공합니다. 색상·글꼴·간격은 스타일, 버튼·입력창은 컴포넌트, 로그인·신청 등 목적을 이루는 흐름은 패턴 관점에서 참고할 수 있습니다. [KRDS 공식 소개](https://www.krds.go.kr/html/site/utility/utility_01.html)

아래 확인표는 이 보일러플레이트에서 활용할 요약·권고이며 공식 가이드라인 전체나 인증 기준을 대체하지 않습니다. 특정 수치·구현 조건이 필요하면 해당 요소의 최신 공식 안내와 프로젝트에서 정한 적용 버전을 확인하세요.

## 적용 범위부터 정하기

| 프로젝트 상황                    | 선택·확인할 내용                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| 일반 서비스·MVP                  | 기존 디자인을 유지하면서 필요한 가독성·일관성·접근성 원칙과 패턴을 선택적으로 참고 |
| 공공 프로젝트                    | 발주·기관 요구사항과 공식 적용 기준을 확인하고 대상 화면·항목·검증 범위를 합의     |
| 이미 디자인 기준이 있는 프로젝트 | 기존 기준과 비교해 도입 이점·충돌·영향을 설명하고 필요한 항목만 변경               |
| 화면과 무관한 DB·서버 작업       | UI 변경이 없으면 상세 화면 설계 생략 가능                                          |

디지털 정부서비스 UI/UX 가이드라인은 공공 서비스의 설계·구현 기준을 설명합니다. 일반 민간 서비스에 모든 항목이 의무 적용된다고 단정하지 않으며 공공 프로젝트의 세부 요구도 문서만으로 추측하지 않습니다. [공식 가이드라인 소개](https://www.krds.go.kr/html/site/utility/utility_07.html)

정부 공식 배너·기관 이름·로고 등은 일반 서비스에 그대로 넣지 않습니다. 파일·폰트·아이콘·코드를 가져온다면 해당 리소스의 이용·저작권 조건도 확인하세요. KRDS 참고와 공식 정부서비스를 나타내는 표현의 사용은 별개입니다.

## 화면 개발 전에 정할 것

1. 비회원·일반 사용자·관리자 등 실제 사용자와 핵심 목표를 정합니다. 관리자 화면은 필요한 서비스에서만 계획합니다.
2. 진입 → 조회·입력 → 확인·제출 → 결과의 주요 흐름을 정합니다. 사용자가 현재 위치와 다음 행동을 이해할 수 있어야 합니다.
3. 화면·메뉴·버튼·입력 항목을 정하고 비슷한 기능의 용어와 동작을 맞춥니다. 공통 화면과 역할별 기능을 구분합니다.
4. 필요한 정상·로딩·성공·오류·빈 상태·접근 제한과 입력 보존·재시도·중요 작업 확인을 계획합니다.
5. KRDS에서 참고할 관련 스타일·컴포넌트·패턴을 골라 공식 URL·버전 또는 확인 기준과 적용·제외 이유를 기록합니다. 모든 컴포넌트를 도입할 필요는 없습니다.

역할별 메뉴 구분은 서버 권한 검사를 대신하지 않습니다. [보안 안내](SECURITY.md), [유효성 검사](VALIDATION.md)를 함께 참고하세요. 폰트와 공통 UI 재사용은 [폰트 안내](FONTS.md)와 [아토믹 디자인 안내](CODEX_GUIDE.md#화면-재사용과-아토믹-디자인-선택-사항)를 활용합니다.

## 화면·사용성 확인표

| 항목             | 사용자 관점의 질문                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| 정보와 흐름      | 이 화면의 목적·현재 위치·다음 행동이 명확한가? 불필요한 반복 입력이 없는가?                       |
| 일관성           | 메뉴·버튼·용어·색상·간격이 같은 의미에 일관되게 사용되는가?                                       |
| 입력             | 라벨·필수 여부·입력 예시가 있고 오류 위치와 수정 방법을 알 수 있는가?                             |
| 상태 안내        | 처리 중·성공·실패·결과 없음·접근 제한을 구분하고 다음 행동을 제공하는가?                          |
| 실수와 복구      | 중복 제출·입력 손실을 막고, 중요한 삭제·취소에 영향에 맞는 확인이나 복구가 있는가?                |
| 키보드와 포커스  | 마우스 없이 주요 작업을 완료하고 현재 포커스를 볼 수 있는가? 모달 종료 후 적절히 돌아오는가?      |
| 의미와 대체 정보 | 제목·버튼·링크·입력창을 적절한 HTML로 표현하고 이미지에 필요한 대체 설명이 있는가?                |
| 가독성과 대비    | 글자가 읽기 쉽고 색만으로 오류·상태를 구분하지 않는가? 선택한 대비 기준을 확인했는가?             |
| 반응형과 확대    | 모바일·화면 확대에서 내용과 조작 요소가 겹치거나 잘리지 않는가? 필요한 표 스크롤이 사용 가능한가? |

이 표는 자체 검토용입니다. 실제 치수·색 대비·키보드 동작 등은 선택한 공식 항목과 적용 기준에 맞춰 확인하세요. 모든 작업에 확인창을 붙이거나 모든 상태를 억지로 만들 필요는 없습니다. 위험과 사용 흐름에 필요한 항목을 선택합니다.

## 현재 기술에 적용하기

Next.js·Tailwind와 기존 컴포넌트로 선택한 기준을 구현할 수 있습니다. 스타일 전체를 복사하거나 별도 UI 라이브러리를 의무적으로 설치하는 방식은 아닙니다. 공식 HTML 예제의 모양뿐 아니라 의미·키보드·포커스·상태 안내를 현재 React 구성에 맞게 검토해야 합니다.

기존 디자인 변경, 리소스 다운로드, 패키지 설치는 필요한 파일·영향을 확인한 뒤 승인 범위에서 진행합니다. 컴포넌트의 위치나 Server·Client 경계를 임의로 일괄 변경하지 않습니다. 단순 수정에는 관련 기준만 적용하며 이미 정한 같은 범위는 반복해서 묻지 않습니다.

## 무엇을 검증했는지 구분하기

코드 검토·타입·린트·빌드·HTTP 응답 확인은 실제 브라우저 사용성 검증과 다릅니다. 핵심 흐름, 필요한 오류·빈 상태, 모바일, 키보드·포커스, 확대·대비를 실제 확인하고 환경·방법·결과·남은 작업을 남기세요. 화면을 보지 못했다면 시각 검증 완료로 기록하지 않습니다.

일부 기준을 참고한 화면을 KRDS 전체 준수 또는 웹 접근성 인증 완료로 표현하지 않습니다. 공공 프로젝트의 별도 평가·인증 요구는 해당 요구에 맞는 검증이 필요합니다. 관련 결정과 예외·근거는 [계획 양식](../plans/README.md)에 기록할 수 있습니다.

## 에이전트에 요청하기

```text
[서비스·화면]의 사용자 역할과 핵심 목표를 정리하고 docs/UI_UX.md 기준으로 계획해 주세요.
기존 디자인을 먼저 확인하고 KRDS의 관련 원칙·컴포넌트·패턴을 제안해 주세요.
일반 서비스의 선택적 참고인지 공공 프로젝트의 요구 기준인지 구분하고,
공식 참고 URL·적용 항목·예외 사유와 실제 브라우저 검증 계획을 보여 주세요.
정부 공식 배너·기관 식별 요소를 임의로 넣지 말고,
아직 화면 변경·리소스 다운로드·패키지 설치는 진행하지 마세요.
```

에이전트의 상세 기준은 [프론트엔드 지침](../.agent/frontend.md#uiux와-krds-참고-기준), 공식 자료 탐색은 [KRDS](https://www.krds.go.kr/)를 참고하세요.
