# 모아(moa) — AI 스마트 옷장

## 프로젝트 개요

- 한 줄 소개: 내가 가진 옷을 사진으로 등록하고, 상황·사이즈·색상·날씨에 맞는 코디를 추천받는 웹 앱입니다.
- 누구를 위한 앱인가: 매일 무엇을 입을지 고민하거나, 가지고 있는 옷을 더 다양하게 활용하고 싶은 사람을 위한 앱입니다.
- 어떤 상황에서 쓰는가: 등교·데이트·면접·여행을 준비할 때, 날씨에 맞는 옷차림을 정할 때, 내 옷과 자주 입는 옷을 정리할 때 사용합니다.

## 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
| --- | --- | --- |
| 1. 회원가입·로그인 및 계정별 옷장 관리 | 이메일 회원가입·로그인·로그아웃, 계정별 옷장 불러오기, 동기화 상태 및 오류 표시 | Supabase Auth로 인증하고, Supabase Data API와 RLS 정책으로 본인의 옷장만 조회·저장 |
| 2. 옷 사진 등록 및 관리 | 사진 업로드·배경 제거, 종류·색상·성별·사이즈 수정, 사진 회전, 옷 삭제, 종류별 필터 | 옷 정보와 사진 데이터를 Supabase `user_closets` 테이블에 저장. 사진 배경 제거는 브라우저에서 ONNX 모델로 처리 |
| 3. 상황과 날씨에 맞는 코디 추천 | 일상·학교·데이트·면접·여행별 추천, 프로필 사이즈·스타일 반영, 날씨와 옷차림 안내 | Open-Meteo API로 기온·강수·바람 정보를 조회. 코디 조합과 점수 계산은 브라우저에서 수행 |

더 만든 기능:

- 마음에 드는 코디 저장 및 저장 목록 관리
- ‘오늘 입었어요’ 버튼으로 착용 횟수 기록
- 옷장 리포트에서 전체 옷 수·착용 횟수·자주 입는 옷 확인
- 옷 색상 분포를 도넛 차트로 표시
- 특정 옷을 포함한 코디 추천 및 추천 제외 설정
- 추천 코디의 옷·사이즈 상세 보기
- 기존 사진의 배경 일괄 제거
- IndexedDB에 계정별 옷장을 캐시하고, 서버 버전이 같으면 사진 전체 재다운로드 생략
- 일시적인 조회 실패 시 제한된 자동 재시도 및 수동 재시도 지원
- 화면 크기와 사진 회전에 맞춘 추천 사진 크기 조정
  
## 기술 스택

- 프론트엔드: HTML5, CSS3, JavaScript, Canvas API, Geolocation API, IndexedDB, ResizeObserver
- 백엔드: Supabase Auth, Supabase PostgreSQL 및 Data API, Row Level Security(RLS). 별도 자체 서버는 없습니다.
- AI·외부 서비스: ONNX Runtime Web 1.22.0, IS-Net 계열 ONNX 배경 제거 모델, Open-Meteo 날씨 API
- 배포: GitHub Pages, GitHub의 Pages 자동 배포 워크플로
- 데이터(어디에, 무엇을):
  - Supabase `user_closets`: 사용자 ID, 옷 목록과 사진, 저장한 코디, 프로필, 착용 횟수, 갱신 시각
  - Supabase Auth: 회원 계정과 인증 정보
  - IndexedDB: 계정별 옷장 캐시 및 마지막으로 확인한 서버 갱신 시각
  - localStorage: 로그인 세션, 기존 옷장 캐시 및 IndexedDB를 사용할 수 없을 때의 저장 대안

코디 추천은 생성형 AI API를 호출하는 방식이 아니라, 색 조화·사이즈·상황·취향·기온 등을 점수화하는 방식입니다. AI 배경 제거 모델은 브라우저에서 실행합니다.

## 실행 방법

별도 빌드나 `npm install` 없이 정적 웹 서버로 실행합니다. 로컬 실행에는 Git과 Python 3가 필요합니다.

1. 저장소를 내려받습니다.

   ```bash
   git clone https://github.com/seungjun02/SBT1.git
   cd SBT1
   ```

2. [설정 안내](docs/SETUP.md)에 따라 Supabase 설정을 확인한 뒤, 프로젝트 폴더에서 서버를 실행합니다.

   ```bash
   python -m http.server 3000
   ```

   Windows에서 `python` 명령을 사용할 수 없다면 `py -m http.server 3000`을 사용합니다.

3. 브라우저에서 [http://localhost:3000](http://localhost:3000)에 접속해 회원가입 또는 로그인합니다. 날씨 기능은 위치 접근 권한을 허용해야 사용할 수 있습니다.

배포 주소(있으면): [https://seungjun02.github.io/SBT1/](https://seungjun02.github.io/SBT1/)

## AI 활용 내역

- 사용한 도구: ChatGPT/Codex. 앱 내부의 사진 배경 제거에는 ONNX Runtime Web과 ONNX 모델을 사용했습니다.
- 주요 프롬프트(그대로 붙여 넣기):

  > 로그인을 하고 웹 사이트가 열리는데 시간이 오래걸리는데 해결 가능한가?

  > 공개 웹사이트에서 나만의 옷장을 불러오지 못했대 오류 수정해줘

  > 웹사이트로 볼때 오늘의 옷장이 짤리는데 오류 수정해줘

- AI가 만든 것 / 사람이 고친 것:
  - AI: 이 대화에서 GitHub Pages 배포 설정, 계정별 IndexedDB 캐시, 서버 갱신 시각 비교, 인증 세션을 활용한 데이터 조회, 조회 실패 복구, 추천 사진 배치·회전 보정, 회귀 테스트와 문서 작성을 수행했습니다.
  - 사람: 필요한 기능과 수정 방향을 제시하고, 공개 사이트를 사용하면서 로그인 지연·옷장 조회 실패·추천 사진 잘림을 확인해 수정 요청과 피드백을 제공했습니다.
- 결과를 확인한 방법:
  - JavaScript 문법 검사: `node --check app.js`
  - 로그인·캐시·오류 복구 테스트 14개와 추천 사진 표시 테스트 6개 통과
  - 실제 Supabase 라이브러리를 이용한 세션 토큰 전달·갱신 및 재시도 설정의 오프라인 검증
  - GitHub Pages 배포 성공 여부와 공개 파일의 HTTP 200 응답 및 수정 코드 반영 확인
  - 사용자 측 공개 사이트 이용 중 오류 제보 반영. 마지막 수정 후 실제 계정 로그인과 화면의 최종 브라우저 검증은 추가로 필요합니다.

## 팀원 역할

이름·학번 대신 수행 역할과 담당 범위를 정리했습니다.

- 기획: 매일의 옷차림 고민을 해결할 사용 흐름과 상황별 추천 조건 정의
- 프론트엔드: 오늘의 옷장·내 옷장·저장한 코디·옷장 리포트 화면, 사진 처리, 반응형 레이아웃 구현
- 백엔드: Supabase 인증 연동, 계정별 데이터 저장·동기화, RLS를 통한 접근 범위 관리
- 검증: 회원가입·로그인·옷 등록·코디 저장 흐름 확인, 오류 재현과 회귀 테스트, 공개 배포 확인

## 아쉬운 점과 다음에 할 일

- 첫 로그인이나 새 기기에서는 사진을 포함한 옷장 전체를 받아야 합니다. 사진을 전용 저장소로 분리하고 썸네일과 지연 로딩을 적용해 초기 전송량을 줄일 계획입니다.
- 배경 제거 모델을 처음 사용할 때 다운로드와 연산에 시간이 걸립니다. 기기 성능별 처리 속도와 실패 시 안내를 개선할 필요가 있습니다.
- 옷 종류는 파일명으로 추정하고 사용자가 수정하는 구조입니다. 이미지 기반 분류를 추가하면 등록 과정을 줄일 수 있습니다.
- 현재 추천은 정해진 조건과 점수에 기반합니다. 실제 착용 피드백을 반영해 추천 품질을 개선할 계획입니다.
- 계정 인증, 다른 기기 간 동기화, 느린 네트워크, 다양한 화면 크기에서 실제 브라우저 검증을 보강할 필요가 있습니다.
